# 风险及恢复

| 风险 | 处理 |
| --- | --- |
| 私有素材丢失 | Git 只能恢复源码；保留两处受控素材副本，定期运行 verify-inputs |
| 迁移包包含密码、资料库与个人信息 | 私有磁盘/受控介质保存；本机素材未加密，不能把 Git 忽略等同于加密或访问控制 |
| 镜像标签被更新或上游删除 | 保留原始镜像 TAR，按整个归档 SHA256 和记录的 Image ID 锁定 |
| 数据库物理备份不一致 | 保留源环境，在独立机恢复验证；SHA256 不能证明事务一致性 |
| RabbitMQ 恢复后像新节点 | 核对 hostname 与 mnesia 路径；保留卷，不自动改名/清空 |
| ONLYOFFICE 补丁随版本失配 | 固定 Seafile 13.0.28 路径及补丁哈希；升版须重新适配与验收 |
| 升级一半失败 | 保存日志、阶段标记、staging 与完整冷备；先分析，再人工恢复一致性备份 |
| 构建中断 | 最终目录只在完成校验后出现；`.partial-*` 是未完成品，不用于部署 |
| 主机运行时缺失 | 预先另行准备 Docker/Compose 与系统工具；包本身不包含这些安装介质 |

构建工具不运行安装器，不触碰 Docker 数据卷。它拒绝覆盖已存在输出，素材对象同哈希但内容不符时也拒绝覆盖。损坏对象应先保留证据，再从可信原包或第二副本恢复；不要修改 manifest 去迎合损坏文件。

部署回滚以升级前同一时点的配置、数据库、资料库、ONLYOFFICE 数据和卷为单位，在空隔离环境优先演练。不得只回滚 YAML 或将旧 TAR 解压覆盖正在运行的数据库。
