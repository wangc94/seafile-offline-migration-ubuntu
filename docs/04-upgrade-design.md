# 保留数据升级

模式 2 的含义是在匹配基线的现有 Seafile 13.0.28 系统上更新部署配置、启用 SeaDoc。它不是 Seafile 12 → 13 等跨版本升级工具。

升级前必须匹配五个已有基础镜像身份、容器和挂载路径、补丁 SHA256、JWT 配置、ONLYOFFICE 卷、RabbitMQ 节点身份与支持的拓扑。检查在停服之前完成，不匹配时退出。

脚本询问独立备份目录，默认 `/opt/seafile-upgrade-backups/<时间戳>`。确认空间后停止相关服务，冷备份配置、资料库、MariaDB、ONLYOFFICE、字体、Caddy、原补丁与三个卷，并记录容器/卷清单。备份生成独立 SHA256SUMS 且立即校验。

升级使用现有业务目录，不解出迁移包中的旧数据库与旧资料库；ONLYOFFICE 三个 external 卷继续指向原实际卷名，不迁移到新空卷。保留 RabbitMQ 原 hostname。只额外导入所需 SeaDoc 镜像。

备份或配置应用前失败时，原脚本尝试恢复原服务；配置应用后失败保留现场和备份，不擅自回滚数据库。回滚需要同一时点的数据库、文件、配置、镜像和卷，不能只换回 Compose。独立 Ubuntu 测试环境须验证这些路径之后，才可用于生产升级。
